# v0.2.0 candidate — manual acceptance

**Candidate:** 0.2.0-rc.1. **Recorded:** 4 October 2026.

These are pending current-candidate hands-on checks. Historical v0.1.0 macOS acceptance is not substituted for them. Use disposable files/vaults, preserve your real data, and record OS, architecture, candidate commit and results.

## Packaged application, each target OS

- [ ] Launch the packaged application without a development server; resize to minimum supported window dimensions.
- [ ] Splash symbol/title centred; panel animations work; reduced motion and keyboard focus are usable.
- [ ] Create a disposable vault, lock it, quit/relaunch, reject a wrong password and unlock with the correct password.
- [ ] Encryption/Decryption start with empty password fields; protected inventory stays hidden while locked.
- [ ] Picker and one-file drop import succeed; multi-file drop, cancelled picker, oversized file and blocked import behave correctly.
- [ ] Decrypt/inspect/edit an authorised text file; save and reopen; verify no plaintext working file appears inside vault storage.
- [ ] Export creates the intended plaintext copy and refuses overwriting an existing destination; cancelled export leaves no success state.
- [ ] Nested PIN rejects incorrect values; parent/nested transfer, text editing, restore and locking behave as documented.
- [ ] Lock/sign-out/relaunch clears protected contents; five-minute idle lock and delayed-timer/resume handling work.
- [ ] Back up a closed disposable vault, restore into a disposable profile and verify unlock and file bytes. Do not copy live changing storage.
- [ ] Identity fingerprint remains stable across restart; copying the public identity works in the actual WebView.
- [ ] Import a public contact, verify independently, replace its key and observe loss of trust; revoked contact stays revoked on reimport.
- [ ] Record native identity-store behaviour. Vault-directory backup alone does not back up the OS credential.

## macOS Touch ID deletion

- [ ] Wrong typed confirmation prevents deletion.
- [ ] Correct confirmation triggers Touch ID from the native command; successful Touch ID deletes only the selected disposable vault.
- [ ] Cancel/fail Touch ID; no vault is deleted and the error allows retry.
- [ ] Lock/sign-out and relaunch do not create biometric unlock access.
- [ ] Where biometrics are unavailable, verify the exact typed-confirmation fallback and its displayed wording.

## Windows and Linux

- [ ] Launch the NSIS-installed application on Windows x64.
- [ ] Launch the AppImage/DEB on a supported Linux x64 desktop.
- [ ] Linux identity acceptance uses an unlocked Secret Service session; absence produces an explicit error, no plaintext credential fallback.
- [ ] Record platform filesystem/export behaviour. Unix mode/no-follow claims are not inherited by Windows.
