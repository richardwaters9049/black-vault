# Black Vault v0.2.0 candidate validation

**Date:** 4 October 2026. **Candidate:** 0.2.0-rc.1. **Branch:** `release/0.2.0-rc.1`.

This record belongs to the current candidate. [v0.1.0 validation](v0.1.0-validation.md) remains unchanged historical evidence.

## Release scope

Offline local vaults, nested compartments, file/text workflows, identity/contact management and native biometric confirmation for permanent vault deletion. Rust transfer crypto/parser exists and is tested; an end-user cross-user package workflow is not part of this candidate. Password vault unlock remains mandatory; biometric vault enrolment is deferred.

- `proc-macro-error 1.0.4`: RUSTSEC-2024-0370, unmaintained, through the native dependency chain.

These are tracked unresolved warnings, not a clean risk-free dependency report. Do not force incompatible transitive versions merely to suppress the output. Recheck the upstream dependency path when updating Tauri. Audit results are date-bound.

## Evidence boundaries

No new hands-on macOS/Windows/Linux GUI acceptance is claimed without a recorded walkthrough. Automated native storage tests use disposable temporary files and do not replace installer, clipboard, real biometric or desktop interaction checks. The real credential-store test uses a unique temporary account and removes only its own credential.

The macOS package is ad-hoc signed, not notarised. Windows/Linux build success is not a Windows ACL/reparse security review or full GUI acceptance. There is no independent cryptographic/security assessment, public distribution commitment or forgotten-password recovery.
